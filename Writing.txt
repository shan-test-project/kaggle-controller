Build a complete, production-quality Android application called Kaggle Controller using Kotlin + Jetpack Compose + Material 3.

This must NOT be a basic Kaggle API wrapper.

The goal is to build a full-featured mobile Kaggle control center / mobile IDE that allows the user to do as much as reasonably possible from Android that they can do on Kaggle's website, while adding powerful mobile-only features for automation, organization, monitoring, offline work, and developer productivity.

The user's Android phone communicates directly with Kaggle through the official supported API/OAuth mechanisms.

There must be NO custom backend server.

Use the attached Kaggle Controller concept image as the visual direction. Improve it substantially and make the application look like a polished modern 2026 developer application.

IMPORTANT:
Before implementing any Kaggle feature, verify the CURRENT official Kaggle documentation/API capability.

Never invent undocumented Kaggle API endpoints.

When a website feature cannot currently be performed through the public API, provide a clearly labelled fallback such as:

"Open in Kaggle"

using the user's browser/custom tab.

Do not fake an API operation.

The application must follow this rule:

Kaggle API first.
Official Kaggle website fallback second.
Local/mobile enhancement third.

Never:

- invent endpoints
- fake execution
- fake schedules
- fake GPU availability
- fake API responses
- silently overwrite notebook changes
- expose credentials
- bypass Kaggle restrictions or quotas

When Kaggle supports something through its API:

IMPLEMENT IT.

When Kaggle supports something only through the website:

SHOW "OPEN IN KAGGLE".

When Kaggle supports something partially:

IMPLEMENT the supported portion and clearly explain the limitation.

The finished app should feel like a serious mobile development environment rather than a simple API client.

Final product identity:

Kaggle Controller
"Your Kaggle workspace, redesigned for Android."
